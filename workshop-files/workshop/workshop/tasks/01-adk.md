## 1.1 Первый LlmAgent

**Шаги:**

1. Открой `examples/01-adk/starter/hello-agent.ts`
2. Запусти **сразу как есть** — `instruction` пустая, вопрос тоже. Запомни что видишь в терминале.

```bash
npx tsx examples/01-adk/starter/hello-agent.ts
# → пустой вывод или generic "Hi, how can I help?"
```

3. Заполни `instruction` (на русском — что агент умеет и как себя ведёт)
4. Заполни `parts[{ text: "..." }]` — задай конкретный вопрос
5. Запусти снова и сравни. Инструкция — контракт, не подсказка.

**Результат:** агент отвечает в терминале на твой вопрос.

```bash
npx tsx examples/01-adk/starter/hello-agent.ts
# → агент: "Привет! Я твой первый ADK агент..."
```

> **✋ Check-in:** у кого агент ответил? у кого пустой вывод или ошибка — разберём вместе.

Скелет: `examples/01-adk/starter/hello-agent.ts`

## 1.2 FunctionTool — агент с инструментом

**Шаги:**

1. Открой `examples/01-adk/starter/tool-agent.ts`
2. Заполни `description` и `execute` у `weatherTool` — верни фейковые данные о погоде
3. Напиши `instruction` — объясни агенту, что для вопросов о погоде он должен использовать инструмент
4. Добавь `weatherTool` в `tools: []`
5. Заполни `main()`: скопируй структуру цикла из `hello-agent.ts` (она та же), добавь вопрос про Москву

**Результат:** в логах видно `[tool called] getWeather({ city: "Москва" })`.

```bash
npx tsx examples/01-adk/starter/tool-agent.ts
# → [tool called] getWeather({ city: "Москва" })
# → агент: "В Москве сейчас 18°C и облачно"
```

**Сломай и почини:** убери `weatherTool` из `tools: []` и запусти снова.
Агент ответит — но данные придумает сам, не вызвав инструмент.
Верни инструмент обратно: вот разница между «агент знает» и «агент вызывает».

> **✋ Check-in:** у кого в логах появилась строка `[tool called]`? Без неё — значит инструмент не подключён.

Скелет: `examples/01-adk/starter/tool-agent.ts`

## 1.3 SequentialAgent — два агента в цепочке

**Шаги:**

1. Открой `examples/01-adk/starter/sequential.ts`
2. Напиши **Агент-исследователь**: принимает тему, возвращает **строго JSON** `{ "facts": ["...", "...", "..."] }` — никакого текста вокруг, только JSON
3. Напиши **Агент-редактор**: принимает факты, переписывает в один абзац
4. Добавь обоих в `subAgents: []`
5. Запусти с темой `"квантовые компьютеры"`

**Результат:** в терминале сначала появляются факты, потом готовый абзац.

```bash
npx tsx examples/01-adk/starter/sequential.ts "квантовые компьютеры"
# → [researcher] { "facts": [...] }
# → [editor] "Квантовые компьютеры используют..."
```

**Обрати внимание:** исследователь возвращает JSON со строгим форматом —
редактор зависит от этого контракта. Если исследователь вернёт прозу вместо JSON,
редактор получит мусор. Именно этот принцип — агент A отдаёт строгий JSON,
агент B читает из него конкретное поле — будет основой волны 2.

> **✋ Check-in:** у кого в выводе появились ОБА агента — `[researcher]` и `[editor]`?

Скелет: `examples/01-adk/starter/sequential.ts`

## 1.4 ParallelAgent — бонус ⚡

**Шаги:**

1. Открой `examples/01-adk/starter/parallel.ts`
2. Допиши агента A и агента B — каждый со своей **фиксированной** темой в `instruction`

> Почему тема фиксирована в instruction, а не передаётся при запуске?
> `ParallelAgent` отправляет **один и тот же** запрос всем суб-агентам одновременно —
> нет механизма передать A одно, B другое в рантайме. Тема должна быть частью
> контракта самого агента.

3. Добавь оба в `subAgents: []`
4. Раскомментируй три строки в `main()` — последовательный прогон и параллельный
5. Сравни время через `console.time`

**Результат:** оба агента отрабатывают одновременно, время заметно меньше.

> На Gemini и Kitana/claude — реальный параллелизм (сетевые вызовы). На
> Ollama (локальная модель) ускорения не будет — один физический GPU/CPU
> обслуживает оба запроса по очереди, это нормально, не баг.

Скелет: `examples/01-adk/starter/parallel.ts`
