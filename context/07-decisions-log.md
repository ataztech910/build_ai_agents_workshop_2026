# CONTEXT: Лог решений — что выбрали и почему

Все решения принятые в процессе обсуждения, включая отклонённые варианты.

---

## Архитектурные решения

### Оркестратор: Google ADK ✅
**Почему ADK а не самописный пайплайн:**
- Встроенный `adk web` дебаггер — визуализация графа агентов на проекторе
- Встроенный Model Routing с автоматическим failover
- `SequentialAgent`, `ParallelAgent` из коробки
- Деплой в Google Cloud если нужно

**Что ADK делает сам (не нужно в Kitana):**
- routing между моделями
- state/memory агентов
- встроенные коннекторы Claude API, Gemini API, Ollama через LiteLLM

**Что ADK не умеет (нужна Kitana):**
- CLI без API ключей
- детекция локального окружения
- Библия проекта

---

### Kitana как прокси, не оркестратор ✅
**Решение:** Kitana = обёртка над CLI. Только отправить промпт и получить ответ.  
Оркестрация — задача ADK.

**Граница:**
```
Kitana.ask()  ←  только это
ADK           ←  всё остальное (агенты, шаги, стейт)
```

---

### @kitana-sdk/server — OpenAI-compatible HTTP ✅
**Уже опубликован на npm.**  
Endpoints: `POST /v1/chat/completions`, `GET /v1/models`, `GET /health`

**Почему OpenAI-compatible а не нативный:**
- ADK подключается через LiteLLM который говорит OpenAI протокол
- Работает как drop-in для n8n, Continue.dev, Vercel AI SDK, etc.
- Участники воркшопа просто ставят `OPENAI_BASE_URL=localhost:4141`

**Открытый вопрос:** нужно проверить поддержку `system` роли, `stream: true`, `tool_calls` для совместимости с ADK.

---

### Публичный API Kitana — класс, не функция ✅
**Выбор:** `new Kitana({ providers: ['claude', 'ollama'] }).ask(prompt)`  
**Отклонено:** функциональный `ask(prompt)` — нет места для конфигурации

**Порядок конфига:**
1. явный аргумент в конструкторе
2. .env переменные
3. автодетект (берёт первый доступный)

---

### Порядок providers = приоритет failover ✅
```typescript
new Kitana({ providers: ['claude', 'ollama', 'gemini'] })
// claude → если упал → ollama → если упал → gemini
```
Участник сам задаёт порядок в конфиге — не хардкод.

## Решения по парсерам

### Twitter/X — убран ❌
**Причина:** платный с февраля 2026, базовый план ~$100/мес.  
**Замена:** Reddit — аудитория похожая, полностью бесплатный.

---

### Instagram — Playwright вместо Apify ✅
**Почему не официальный Instagram API:**  
Meta убрала доступ к комментариям из Graph API в 2020.

**Почему не Apify:**  
Дополнительная зависимость, нужен аккаунт, платный.

**Почему Playwright:**
- Прямой контроль
- Перехват GraphQL `/graphql/query` — надёжнее чем DOM скрейпинг
- Сессия сохраняется, повторный логин не нужен

**Важная деталь — stealth:**  
`playwright-extra` + `puppeteer-extra-plugin-stealth` обязательны.  
Без stealth Instagram блокирует headless Chromium через несколько запросов.

**Для воркшопа:** использовать запасной/тестовый аккаунт, не основной.  
Лимит 50 комментариев за раз — безопасно.

**Если 2FA:** `IG_HEADLESS=false` показывает браузер.

---

### Telegram — gramjs (MTProto) ✅
**Почему не Bot API:**  
Bot API не даёт читать комментарии каналов.  
gramjs = полноценный клиент как официальное приложение.

**Сессия:** сохраняется в `.telegram_session` — первый логин один раз.

---

### Единый ParseResult интерфейс ✅
Все парсеры возвращают одинаковый формат.  
Агенты не знают из какой соцсети пришли данные.  
Можно заменить парсер не трогая агентов.

## Решения по воркшопу

### Формат заданий — шаги + результат, без решений ✅
**Отклонено:** задания + подсказки + решения  
**Причина:** технари, решения уберут мотивацию разбираться самим.  
Решения — в отдельной ветке `solutions/` репо.

### Структура файлов — папка tasks/ + index.md ✅
```
tasks/index.md       — карта
tasks/01-adk.md      — волна 1
tasks/02-api.md      — волна 2
tasks/03-kitana.md   — волна 3
```

### Стартовый код — скелеты с TODO ✅
Импорты и типы есть, реализация пустая.  
Смотреть в `examples/` только если завис больше 5 минут.

### Эксперимент "один промпт vs три агента" ✅
Центральный момент воркшопа. Доказывает практически а не на словах.  
Запускаешь оба варианта на одних данных → зал видит разницу.

**Почему вариант A хуже:**
- модель оптимизирует всё сразу → компромисс по каждой задаче
- валидатор не критикует — он сам только что написал эти офферы
- нельзя заменить один шаг на более сильную модель

## Решения по Библии проекта

### Библия = папка с файлами, не БД ✅
```
.kitana/bible/
  mission.md
  progress.md
  snapshots/
```
**Причина:** читаемо людьми, легко дебажить, не нужна БД.

### bible.ts = только типы и I/O ✅
Не логика, не агент — просто TypeScript типы и функции чтения/записи.

### Кто обновляет — агент по протоколу ✅
После каждого шага агент обязан вызвать `bible.update(step, result)`.  
Это часть контракта агента, не опционально.

## Решения по сжатию контекста

### Dense format вместо китайских иероглифов ✅
**Предложение:** сжимать в китайские иероглифы (информационно плотнее).

**Почему отложено:**
- Слабые локальные модели (ollama с llama3.2) плохо понимают китайский
- Парадокс: сжимаем для слабой модели, но слабая модель не читает сжатое
- Нужны тесты на реальных моделях

**Принятый подход — dense format:**
```
# было (verbose):
"The parser agent successfully extracted 47 comments from @channel..."

# стало (dense):
parser: 47 comments @channel jan-mar2026
signals: automation×12 scaling×8 nocode×6
```
~60-70% сжатие, работает на любой модели.

### Три режима compressor ✅
1. авто — по размеру контекст окна модели
2. конфиг — разработчик задаёт `maxTokens` в `.env`
3. агент-саммаризатор — отдельный быстрый вызов

**Для v0.1:** только авто режим. Остальные после фидбека от пользователей.

## Отклонённые идеи

### Vercel AI SDK адаптер — отложен
Нужен для Electron приложения (будущий проект).  
На воркшопе не нужен — нет фронтенда.  
Трек: `@kitana-sdk/vercel` в v0.3.

### ADK адаптер для Kitana — отложен
`@kitana-sdk/adk` — адаптер чтобы Kitana выглядела как провайдер для ADK.  
Оказалось не нужен для воркшопа — `@kitana-sdk/server` решает через OpenAI-compatible API.

### Один монорепо — отклонено
**Предложение:** один репо для воркшопа + Kitana.  
**Решение:** раздельные. Воркшоп = отдельный репо. Kitana = `ataztech910/kitana` (уже есть).

### LangChain/LlamaIndex вместо ADK — отклонено
ADK выбран потому что:
- встроенный `adk web` визуализатор
- нативная интеграция с Google провайдерами
- проще для демонстрации на воркшопе
