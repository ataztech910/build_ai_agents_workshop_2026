Черновик содержания слайдов для Close (25 мин по обновлённой таблице блоков
в `context/17-intro-slides-ru.md`/`slides-app`): демо ведущего
(`tasks/03-closing.md`) + быстрый круг.

**Изменилось с прошлой версии этого файла:** Close вырос с 5 до 25 минут —
вместо одной ноды n8n поверх одного агента показываем полный 3-звенный
пайплайн: `planner` (новый presenter-only агент) → data portal → `lead-
finder` (Block 3) → n8n группирует результат. Контент сверен с
`tasks/03-closing.md` и `examples/03-closing/planner.ts` — оба проверены
живыми прогонами (CLI и `adk web`/HTTP).

Заголовок: "Close: Real Conditions". Подзаголовок: то, что построили

## Close · Слайд 2 — Архитектура пайплайна

```
[planner]  → решает канал (новый агент)
    ↓
[data portal]  → реальные комментарии (Block 3)
    ↓
[lead-finder]  → analyst → copywriter → validator (Block 3)
    ↓
[n8n]  → Sort → Set — группирует и форматирует результат
```

Фраза: *"Два независимых ADK-агента за двумя HTTP-эндпоинтами. n8n дёргает
оба по очереди и обрабатывает результат между ними — оркестрация в n8n, не
новый TypeScript-код."*

## Close · Слайд 3 — planner: ещё один LlmAgent

```ts
export const agent = new LlmAgent({
  name: "planner",
  model: pickModel(),
  instruction: `Given a business description, pick ONE channel: ...`,
});
```

Фраза: *"Тот же рецепт, что и hello-agent.ts в самом начале — model,
instruction, всё. Просто теперь его вызывает не человек через терминал, а
n8n через HTTP."* Явная отсылка к Part 1 ("model decides what's next") —
planner в чистом виде делает именно это: решает, какой источник данных
использовать, а не просто обрабатывает то, что дали.

## Close · Слайд 4 — n8n демо

Диаграмма нод (не код — это демо ведущего, зал смотрит):

```
Manual Trigger → HTTP (planner /run) → HTTP (portal GET)
  → HTTP (lead-finder /run) → Sort → Set (итоговый список)
```

Что показываем вживую (из `tasks/03-closing.md`, оба `adk web` сервера уже
подняты и прогреты заранее):
1. Жмём **Execute Workflow** в n8n
2. Зал видит подсветку нод одна за другой: planner выбирает канал → портал
   отдаёт данные → lead-finder гоняет своих 3 агентов → n8n сортирует и
   форматирует
3. Показываем итоговый список — та же механика, что участники только что
   писали руками, теперь работает без участия человека
