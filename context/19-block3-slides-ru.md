не абсолютно по колоде — Block 2 ещё не расписан (Шаг 3 для него не сделан),
так что абсолютные номера пока не зафиксированы. Когда дойдём до сборки в

остановится Block 2.

Контент сверен с текущим состоянием `examples/02-api/` (проверено живыми
прогонами сегодня, не то, что было на момент старой версии

## Block 3 · Слайд 1 — Section: Block 3

## Block 3 · Слайд 2 — Что строим

Не новая архитектура — тот же `SequentialAgent`, что и в Block 2, три агента
вместо двух:

```
Комментарии → [analyst] → топ-3 лида
            → [copywriter] → персональный оффер каждому
            → [validator] → отклоняет шаблонные, переписывает
```

Фраза: *"Такой же LlmAgent/SequentialAgent, как в Block 2 — здесь ново не
устройство пайплайна, а откуда берутся данные."*

## Block 3 · Слайд 3 — Заглушка → реальный API

Ключевой слайд блока (это и есть тема "ADK + API", дословно из
`tasks/02-api.md`): **не про то, какая LLM отвечает** (это уже в Block 1 —
`pickModel()`), а про то, как затащить реальные данные вместо
захардкоженного массива.

```ts
async function pickComments(): Promise<LeadComment[]> {
  return FAKE_COMMENTS; // no network needed, always works

  // const res = await fetch(`${DATA_PORTAL_URL}/api/comments?channel=startups`);
  // ...
}
```

Тот же toggle-паттерн, что и `pickModel()` — раскомментировать одну ветку.
Три варианта, от простого к сложному (показать как список, не запускать все
три вживую — только первый):

1. `FAKE_COMMENTS` — дефолт, ничего настраивать не надо
2. Учебный портал `workshop-data-portal.vercel.app` — без ключей и логина,
   тот же формат ответа, что вернул бы реальный парсер
3. `lead-finder-v3/telegram-parser.ts` — настоящий Telegram, нужен свой
   `TG_API_ID`/`TG_API_HASH` и логин по телефону/2FA

## Block 3 · Слайд 4 — Демо: что смотрим (перед живым кодом)

Слайд-чеклист, держим на экране, пока крутим терминал рядом (не читаем с
него — это ориентир для зала, что именно сейчас произойдёт):

1. Запустить `lead-finder.ts` на дефолте (`FAKE_COMMENTS`) — в консоли по
   очереди `[analyst]` → `[copywriter]` → `[validator]`
2. Раскомментировать вариант с fetch к порталу в `pickComments()`
3. Запустить ровно ту же команду ещё раз — смотрим: те же три агента, тот же
   код, но в выводе уже реальные лиды

Итог, который должен считаться залом: `leads_result.json` во второй раз —
про других, настоящих людей, а в трёх агентах при этом не поменялось ничего.

## Block 3 · Слайд 5 — adk web: граф агентов

```bash
npx adk web examples/02-api
```

Открыть в браузере, показать граф `analyst → copywriter → validator`,
прогнать запрос, показать как `validator` реально отклоняет и переписывает
шаблонный оффер (не просто пропускает всё насквозь — видно разницу
до/после).

Фраза (из `02-workshop-plan.md`, ещё актуальна): *"Агент ведёт себя
странно — сюда смотришь первым делом."*

## Block 3 · Слайд 6 — Теперь пишете сами (17 мин)

- Задание 2.1 из `tasks/02-api.md`
- Скелет: `examples/02-api/starter/lead-finder.ts`
- Порядок: заполнить `pickComments()` (начать с дефолта) → написать
  инструкции трём агентам → собрать `SequentialAgent` → прогнать
- Главный эксперимент: поменять `ICP` и прогнать снова — те же комментарии,
  другие лиды
- Точка синхронизации: двое показывают разные `ICP` на одних данных, зал
  видит разных лидов ("вау"-момент — из `02-workshop-plan.md`, всё ещё
  работает)
- Подсказка застрявшим: "Что вернул `analyst`? Посмотри на первый JSON в
  консоли, прежде чем чинить `copywriter`"
