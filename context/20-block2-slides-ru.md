## Block 2 · Слайд 2 — Один агент vs несколько (ключевой момент)

Два варианта на одних и тех же входных данных:

```
Вариант A — один промпт:
  "Найди лидов + напиши офферы + проверь" → один LlmAgent

Вариант B — три агента:
  analyst → copywriter → validator (SequentialAgent)
```

Не диаграмма процесса — сравнение результатов. На слайде просто эти два
варианта side-by-side, без кода.

## Block 2 · Слайд 3 — Демо: смотрим оба результата

Живой код, не слайд с текстом (по аналогии с чек-листом демо в Block 3):
запускаем вариант A, потом вариант B на тех же данных, читаем оба
результата вслух/на экране.

Что должен заметить зал (обсуждение после прогона, не на слайде — держим
как заметку для ведущего): в варианте A валидатор-шаг ничего не
раскритиковал — модель только что сама это написала, ей нечего себе
возразить в рамках одного контекста.

Фраза (дословно из `02-workshop-plan.md`, ключевая фраза блока):
*"Модель в одном промпте идёт на компромисс по каждой задаче. Три агента
оптимизируют каждую задачу отдельно."*

## Block 2 · Слайд 4 — SequentialAgent: как это устроено

```ts
const researcher = new LlmAgent({ name: "researcher", model, instruction: "..." });
const editor = new LlmAgent({ name: "editor", model, instruction: "..." });

export const agent = new SequentialAgent({
  name: "research-pipeline",
  subAgents: [researcher, editor],
});
```

Фраза: *"Каждый суб-агент — это просто `LlmAgent`, тот же самый, что в
Block 1. `SequentialAgent` только определяет порядок и прокидывает вывод
одного в следующий."*

Показать `pickModel()` — та же строка-тумблер, что и в Block 1, ничего
нового учить не надо.

## Block 2 · Слайд 6 — Бонус: ParallelAgent (если время есть)

Не отдельный тайм-слот — для тех, кто закончил 1.3 раньше.

```
SequentialAgent: A → B         (ждём A, потом B)
ParallelAgent:   A ⇉ B         (оба сразу, один и тот же запрос обоим)
```

- Задание 1.4, скелет `examples/01-adk/starter/parallel.ts`
- `ParallelAgent` — у обоих суб-агентов фиксированная тема в `instruction`
  (в отличие от `SequentialAgent`, тему нельзя передать по-разному каждому
  в рантайме)
- Замерить время через `console.time` — сравнить с последовательным
  запуском
- Оговорка: реальное ускорение на Gemini/Kitana-claude (сетевые вызовы), но
  не на Ollama — один GPU/CPU обслуживает оба запроса по очереди, это не
  баг
